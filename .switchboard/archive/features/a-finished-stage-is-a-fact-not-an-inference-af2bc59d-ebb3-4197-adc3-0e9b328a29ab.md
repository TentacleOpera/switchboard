# A Finished Stage Is a Fact, Not an Inference

**Complexity:** 5

## Goal

Make the end of a pipeline stage something the system can read rather than guess. Every completion signal today is a proxy — plan-file mtime, terminal silence, a card column that moves on dispatch rather than on finish — and none of them can express reviewed at all. This feature gives each stage exactly one committer, stamps that commit with a machine-readable stage marker, and fixes the handoff that was supposed to carry a finished feature into review but instead had the lead hand-writing prompts straight to its reviewer, per subtask.

## How the Subtasks Achieve This

- **Coding Team — The Lead Sends the Whole Feature to Review, Through Board Dispatch**: Changes the Coding team's reviewer from `relationship: 'reviewer'` to `reports-to-head`, which stops the pair preset installing a standing order on the lead telling it to compose a summary and hand work over directly — the observed behaviour, verbatim, and the order that wins today because it is self-contained where the board route is not. Rewrites the `headPrompt` to be feature-level and single-action: one `POST /kanban/dispatch` on the **feature's** planId once every subtask is done, with `from` kept intact because team-scoped reviewer routing resolves on it and silently misroutes without it.
- **Retire Auto-Commit — Leads and Reviewers Commit, and a Review Commit Means Done**: Deletes `autoCommitForCodeReview`, which runs `git add -A` before code review and sweeps eleven files of board churn into a commit whose message describes three files of real work. Gives the planner and the reviewer a commit strategy across all three layers that currently exclude them — a role that fixes bugs and a role that authors plan files are both code-writing roles — and tightens `whenDone` so agents stage by path instead of greedily.
- **Stage Markers in Git — a Commit Says Which Stage Finished**: Adds `Switchboard-Stage` and `Switchboard-Plan` trailers to the commits those roles now make, giving the orchestrator's tick and the board a durable, attributable, verifiable fact where they have only ever had estimates. Trailers rather than a subject-line convention, so parsing does not depend on text a human writes. Explicitly additive: existing detection stays until markers prove themselves.
