# Automation Is Three Exclusive Modes

**Complexity:** 7

## Goal

The AUTOMATION tab becomes a three-way choice — agent-managed, scheduled, external — with one interval, one on/off, and one status line. Today it stacks column rules, kanban automation rules, a scheduler job list and an oversight-agent checkbox as peers, with two clocks and three start affordances on one screen, plus a fourth exclusive mode (the attended oversight pass) that never appears in the selector at all. It also hands the worktree strategy back to the user, who currently has it stashed and forced out from under them every time the orchestrator arms. This is the foundation the orchestrator work sits on: agent-managed mode has to exist before there is anything to start.

## How the Subtasks Achieve This

- **Worktree Strategy Is the User's Choice, and the Agent Obeys It**: Deletes `applyOversightWorktreeTopology`, the `orchestration_prior_feature_worktree_mode` stash key and the dead reconciler that existed only to unwind the forced value — and **adds the control the user is missing**. `feature_worktree_mode` is currently broadcast to the webview but read by nothing and written by no UI at all, so a radio goes onto the Worktrees tab alongside the deletion. A one-time drain restores the real setting for any install a crashed orchestrator session left pinned to `per-feature`. This is also what removes the reason `Miscellaneous` was ever invented — with one checkout and one team at a time, a featureless plan no longer has nowhere to be coded.
- **Retire the Scheduler Surface, Keep Its Two Jobs**: Deletes the second clock — the job list, the source and target pickers, the per-job interval, the per-job START/STOP and COPY PROMPT, the target-contract round-trip, and the per-job timer engine behind them. `fetch-plans` and `reconcile` survive as two checkboxes on the run sheet's single clock, because they are persisted, start from activation, and are editable nowhere else; `custom` jobs are retired on read via the pattern the config service already uses, with a one-time notice naming what stopped. A pure subtraction that shrinks the tab before the mode rewrite lands on it.
- **AUTOMATION Tab — Three Exclusive Modes, and Almost No Other Controls**: Collapses the tab to three radios, one interval and one switch. Folds the run sheet in as Scheduled, turns the oversight agent into Agent-managed, restores the wake interval that shipped in July and was dropped in August, and retargets `normalizeAutomationMode` so every shipped cohort — including installs persisted as `internal` with the oversight flag ticked — lands on the right mode. It also carries the two surviving pieces of the retired PM-button subtask: wiring the `orchestratorStartResult { success: false }` message that is posted today and handled nowhere, and adding the command-palette entry that no contributed command provides.
- **Delete the Attended Oversight Pass**: Removes `OversightPassService`, its three routes, the `isAutomationArmed` closure and its durable state files. It is the same two-lane machine as the orchestrator tick, resolves its queue once at start so a mid-pass arrival is invisible to it, and is a hidden fourth exclusive mode enforced by a 409 that never appears in the selector. The larger half of the work is the control plane: 38 references across four `.agents/` files plus a generated protocol catalog and the `.claude/` mirrors, all of which would otherwise keep instructing agents to call routes that 404.
