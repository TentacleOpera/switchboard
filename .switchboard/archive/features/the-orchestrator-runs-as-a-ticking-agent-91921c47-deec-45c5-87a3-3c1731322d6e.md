# The Orchestrator Runs as a Ticking Agent

**Complexity:** 6

## Goal

Turn the orchestrator from a one-shot batch manager into an agent that wakes on an interval, assesses the board, takes at most one action per lane, and stops. Starting it becomes a conversation rather than a button press — the agent runs a pre-flight, reports what is missing, proposes a session goal, and waits for an answer before anything runs unattended. Agents get a file inbox so an orchestrator that is not a pty has a reply channel at all, and the /switchboard skill shrinks from a 631-line conversational board console to a two-step launcher now that the browser board is the console. Everything here consumes the modes and settings established by the automation-modes feature, which must land first.

## How the Subtasks Achieve This

- **Orchestration Starts as a Conversation, Not a Button Press**: Start seats the orchestrator and hands it a pre-flight instruction — is there a coding *team* (not merely a coding agent) for the features in scope, a planner, a researcher if the research prompt is live, does the board match the worktree strategy, is there anything to do at all. It reports what is missing without fixing it, proposes a session goal, and writes `.switchboard/orchestrator/session.md` only once the user answers. `POST /orchestration/start` is redirected into the same sequence so both doors behave identically rather than leaving one that silently arms.
- **Orchestrator Persona — One Tick, One Action, No Miscellaneous**: Rewrites the persona for interval operation — two independent lanes with capacity guards, one dispatch per lane per wake, context cleared every tick and rebuilt from the session file, silent when idle, a wake arriving mid-pass dropped rather than queued. Deletes the kickoff ceremony, the forced grouping and the `Miscellaneous` sweep, and widens scope so feeding the planning lane becomes routine work rather than an escalation.
- **Agents Post Updates to a File Inbox the Orchestrator Reads**: Adds `.switchboard/orchestrator/reports/` so a lead can post finished / blocked / question / status as files, reusing the proven-but-unused `ScheduledJobsService` inbox conventions (`writeInstruction` has no caller anywhere in `src`). This is what makes the tick's second lane-guard signal — ask the lead — work when the orchestrator is an IDE sidebar or a cloud session rather than a pty. Nothing is deleted: completion reports stay in plan files and `ptySendPrompt` stays.
- **`/switchboard` Becomes a Launcher — Two Steps, Not a Console**: Reduces the skill to start the board if nothing answers, then start the orchestration agent into the pre-flight above. The 631-line conversational board console predates `npx switchboard`; the browser board is now the console, and a skill that narrates the board in markdown is a worse version of a UI the user can open.
