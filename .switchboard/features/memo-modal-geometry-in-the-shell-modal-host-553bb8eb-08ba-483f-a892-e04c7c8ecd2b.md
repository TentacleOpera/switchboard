# Memo modal geometry in the shell modal host

**Complexity:** 5

## Goal

The shell's modal host sizes, positions and dismisses #modal-dialog without reference to the panel inside it, and all three defects land on the Memo panel. The close button overlaps the workspace dropdown's last 12px; the fixed 700px dialog height leaves ~190px of opaque dead space below the memo controls that swallows backdrop-dismiss clicks; and a panel that has finished its job cannot ask to be closed, so the operator hunts for the × after every capture. All three are fixed in shell.html/shell.js/memo.html/memo.js/transport.js by making the corner reservation, the dialog height, and the frame's ability to report its own state explicit contracts the panel can honour.

## How the Subtasks Achieve This

- **Memo Modal Close Button Overlaps The Workspace Dropdown**: Turns the dialog's top-right corner into a named, *derived* reservation — `#modal-dialog` gains `--modal-close-inset` / `--modal-close-size` tokens that `#modal-close` itself consumes, with `--modal-close-reserve` computed from them (42px), so the reserved width can never drift from the button it reserves for. `memo.html` mirrors the resolved value as `.memo-header { padding-right: 42px }`, moving the workspace `<select>` out from under a button that — being a sibling of the iframe — wins every hit test regardless of z-index. Two static CSS declarations; no new state, listener or message.
- **Memo Modal Is Oversized: Dead Space Below The Memo Swallows Backdrop-Dismiss Clicks**: Replaces the dialog's fixed `height: min(700px, 88%)` with `height: var(--modal-content-height, min(700px, 88%))` plus a floor and a cap, so a panel that reports nothing keeps today's exact behaviour. `memo.js` gains an rAF-coalesced `ResizeObserver` that posts its root-element box height to the shell; `shell.js` verifies the sender frame, clamps the value, stores it **per panel id**, and resolves it in `openModal` (adding back the dialog's own 1px border, measured). The dialog then ends where the memo ends, so the region the operator aims at for dismissal is genuinely `#modal-backdrop`.

- **Dismiss The Memo Modal After Copy Prompt / Send To Planner**: Builds the frame→shell request channel the other two subtasks assume exists. `transport.js` gains `__switchboardCloseModal` beside the existing `__switchboardSwitchPanel` (same iframe guard, same `'*'` target origin); `shell.js` gains a `closeModalPanel` arm on its cross-frame listener that origin-checks the sender and dismisses only the overlay that is actually open, routed through `closeModal()` so rail state, focus return and `aria-expanded` all reset as they do for the ×, the backdrop and Escape. `memo.js` requests dismissal only on a real success (`!isError && memoCleared` — the same gate that already earns the `✓` flash), coalesced because one click delivers `memoPromptResult` twice in the browser, and cancelled on a fresh submit or on typing.

## Dependencies & sequencing

- **The three subtasks share one seam: `shell.js`'s cross-frame `postMessage` listener.** The dismissal subtask adds a `closeModalPanel` arm to it; the dead-space subtask adds a height-report arm to the same listener with the same `event.origin !== location.origin` check. This is the reason all three now live in one feature rather than two — they are edits to the same function, and splitting them across features guaranteed a collision.
- **Shipping order is fixed: close-button reservation first, dead-space sizing second, dismissal third.** The first two edit the same rule — `#modal-dialog` in `src/webview/shell.html` (lines 165-177). The first adds the `--modal-close-*` tokens; the second changes the `height` lines and must **preserve** those tokens rather than replace the block. Its Proposed Changes carries them as annotated context for exactly this reason.
- **One agent stream, not two worktrees.** The project PRD's orchestration contract ("one agent stream per provider file; same-file parallel edits collide") applies directly: dispatching these in parallel guarantees a conflict on that block. Sequential in a single stream is the intended execution.
- **Neither subtask is a prerequisite for the other's *correctness*, only for its merge.** The reservation is inert with respect to height, and the height mechanism is inert with respect to the corner. If the order is reversed, the close-button subtask must *add* its tokens to whatever `#modal-dialog` block it finds instead of replacing it.
- **Guards that must hold in both:** no confirmation dialogs anywhere on the close path (`CLAUDE.md`); `shell.js` must remain free of native `title` assignments (asserted by `src/test/shell-modal-panel-contract.test.js` and `src/test/shell-terminal-strip.test.js:503`); `closeModal` must never destroy or reload the modal frame (same contract test) — the memo's live document, WebSocket and pending autosave depend on it.
- **Dismissal lands last, and its arm must be *added* to the listener, not replace it.** If the dead-space subtask has already shipped, `shell.js`'s bridge carries a height arm; the dismissal arm goes beside it and both keep their origin check. If dismissal ships first, the reverse applies. Neither may rewrite the listener wholesale.
- **`closeModal` must still write nothing on the way out.** `shell.js` carries an explicit comment that it performs no flush, no save and no postMessage — `memo.js` owns its debounced save. The dismissal subtask makes the frame *ask*; the shell must still write nothing. This is the one rule that a "while I'm here, flush the memo before closing" instinct would quietly break.
- **Only `memo` is `presentation: 'modal'` today** (`src/services/headlessPanelHtml.ts:521`). All three fixes live in the generic modal host so the next modal panel inherits them; none may assume memo is the only consumer. The dismissal helper must also no-op on the full-page `/memo` route, which has no host to ask (`window.parent === window`).
