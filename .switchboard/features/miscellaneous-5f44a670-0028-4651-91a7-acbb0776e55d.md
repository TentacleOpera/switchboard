# Miscellaneous

**Complexity:** 5

## Goal

Catch-all feature for the two standalone Browser Switchboard plans left after the orchestration kickoff scan. They share no capability theme and are grouped only so the batch has no ungrouped remainder. One of the two is contested: the Connections Jobs Tab plan builds a UI over the instruction-inbox and standing-jobs subsystem that a subtask of External Orchestration Surface deletes entirely, on later evidence. That conflict is escalated in the session log and the Jobs Tab subtask must not be coded until a human resolves it.

## How the Subtasks Achieve This

- **Connections Jobs Tab — Standing Jobs, Inbox Lifecycle and Run-Log View**: Fills the Connections panel's Jobs sub-tab with a read-mostly activity view over the standing-job / instruction-inbox / declared-move machinery — six verbs, three new KanbanDatabase read methods, and a resolver branch so the connections-stamped webview can reach them. **Contested — do not code.** See Dependencies & sequencing.
- **The Markdown Editor's Live Preview Renders With a Different Engine Than the View It Predicts**: Moves four of the five `renderPreview` call sites off VS Code's CommonMark round trip and onto `renderMarkdown`, the engine their view mode already uses, so the split-view preview predicts the saved result. On the standalone host the same change is the difference between a working preview and a permanent "Nothing to preview" — `markdown.api.render` has no standalone implementation. `project.js` is deliberately left alone.
