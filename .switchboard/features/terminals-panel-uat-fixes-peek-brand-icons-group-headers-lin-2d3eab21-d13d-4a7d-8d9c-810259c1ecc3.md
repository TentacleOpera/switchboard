# Terminals Panel UAT Fixes: Peek, Brand Icons, Group Headers, Link-Up

**Complexity:** 6

## Goal

Four defects found in terminals.html during UAT, all in src/webview/terminals.js and its stylesheet. Peek seats an unseated terminal through the displacing composer path and dismiss has no snapshot to restore, so restore permanently evicts a grid occupant. The pane header and the new-terminal role picker render no brand icon for any agent, so an Antigravity agent is never visually branded where it is chosen. The sidebar invents a synthetic Workspace Root group and renders a header for every configured folder mapping, including empty ones and a sole one that disambiguates nothing. Link-up still offers an Instant mode that fires an unrecorded, unrevocable one-shot prompt and is the default.

> **Scope correction (verified against `src/` at HEAD, 2026-08-14):** the pane-header brand icon named in the Goal above **is already implemented** — `updatePaneElement` builds a `.pane-brand-icon` from the same two resolvers the sidebar row uses (`terminals.js:4510-4537`), with matching CSS including a terse-layout size override (`terminals.html:1149-1176`). Only the **role picker** remains iconless. If the running panel shows no icon in a pane header, the installed VSIX is stale — rebuild rather than re-implementing it. The Goal text is preserved as written; this note is the correction.

## How the Subtasks Achieve This

- **Make Peek Non-Destructive: Restore the Exact Grid the Peek Interrupted**: Adds a `peekRestoreState` snapshot captured in `peekTerminal` after any previous peek is restored and before the displacing seat runs, and restores it in `dismissPeek`. The snapshot carries the pane arrays, pins, modes, focus, the active group **and that group's membership** — because the locked seat path enrols the peeked terminal via `addTerminalToActiveGroup`, and a membership left behind is silently re-applied by the next `seatActiveGroupPage`. It also stops the peek seat taking the caret, which is what makes the Escape dismiss reachable and stops post-restore keystrokes landing in the wrong agent. This is the subtask that makes `peek` a glance instead of an edit.
- **Show the Antigravity Brand Icon Everywhere terminals.html Names an Agent**: Adds a brand `<img>` and the CLI name to each option in the new-terminal role picker, so choosing "Researcher" visibly says `Researcher · Antigravity CLI` instead of naming no brand at all — the surface an operator actually uses to pick an agent. It also collapses the duplicated brand-resolution logic onto the single `CLI_BRAND_ICON_KEYS` table, retiring a dead second copy that would have silently mis-resolved the next brand added to it.
- **Stop the Terminals Sidebar Inventing Workspace Group Headers Nobody Asked For**: Filters unpopulated folder mappings out of the render entirely and suppresses the heading for a sole populated group with no worktree children, so a heading appears only when it separates something. Because the header carries the only per-folder `+` and `#btn-new-terminal` no longer exists, it moves spawn-location choice onto the group-tab-strip `+` using the existing `buildWorkspaceList()` projection and `{ parentRoot }` target shape. This is what removes the group the user never created.
- **Delete Link-Up's "Instant" Mode — Standing Orders Is the Only Mode**: Deletes the mode selector, its persisted setting, its one-shot `ptySendPrompt` arm and the two functions that existed only to serve it, leaving Link-up a single-purpose dialog whose every instruction is listed and individually revocable. Where the store is unreachable it replaces the silent fallback-to-Instant with an honest disabled state, so the modal never quietly does something the operator cannot see or undo.

## Dependencies & sequencing

- **One hard ordering constraint:** *Show the Antigravity Brand Icon* must land **before** *Stop the Terminals Sidebar Inventing Workspace Group Headers*. Both edit `buildRolePicker` — the first rewrites its option rows, the second adds a spawn-location control above them. The reverse order forces a manual merge inside one loop body.
- **Everything else is independent.** *Make Peek Non-Destructive* and *Delete Link-Up's "Instant" Mode* have no ordering relationship to each other or to the pair above, and can land at any point in the sequence.
- **All four edit `src/webview/terminals.js`, so the edit stream serialises** even where the logic does not (the project's one-agent-stream-per-file rule). Their function spans do not overlap: peek touches `peekTerminal` / `dismissPeek` / `applyPeekClasses` / `sanitizePaneAssignments` / the rename block; brand icons touch `brandIconForCliLabel` and `buildRolePicker`; sidebar groups touch the `renderSidebarList` grouping section, the group-tab-strip `+` and `buildRolePicker`; link-up touches only the 8090-8540 band. Two also edit `src/webview/terminals.html` (brand icons: `.role-option`; link-up: the `#link-modal` markup) in unrelated blocks.
- **Suggested order:** *Delete Link-Up's Instant Mode* → *Show the Antigravity Brand Icon* → *Stop the Sidebar Inventing Group Headers* → *Make Peek Non-Destructive*. This puts the fully isolated subtask first, honours the one hard constraint in the middle, and leaves the largest state-machine change last so it rebases onto a settled file rather than the other way round.
- **Prerequisites and guards:** no migration or feature flag is needed — `terminals.linkMode` is orphaned in place rather than deleted (shipped-state rule), and the sidebar's synthetic bucket is retained as an internal fold target so the existing fold contract stays intact. One shipped contract assertion is deliberately reversed: `src/test/multi-parent-terminals-contract.test.js:307` currently requires the `empty-parent-notice`, and the sidebar subtask must invert it in the same change. Test **execution** is out of scope for this dispatch per the session directive; the authoring is not.
