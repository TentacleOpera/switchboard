# The .claude/skills Mirror — Register the Orphan Skill and Make Divergence Loud

**Complexity:** 5

## Goal

Close a live path in which an extension activation deletes a working skill with no diagnostic, and stop the failing check from printing the one remedy that performs the deletion. The delegates skill was committed to .agents, to .claude, and to the prune ledger but never to MIRROR_MANIFEST, so the ledger lists 48 skills, the generator produces 47, and the prune loop removes the difference. The failure and the fix are indistinguishable at every automated gate: follow the check's own instructions at HEAD and it deletes the skill and goes green. One subtask fixes the instance and clears the first blocker in CI; the other fixes the mechanism, so the next skill added without a lockstep manifest edit is archived and named rather than silently unlinked.

## How the Subtasks Achieve This

- **`mirror:check` is red because the `delegates` skill was never added to MIRROR_MANIFEST**: appends the one missing manifest entry, pre-verified byte-identical against the committed mirror (sha256 `ac7488a9…`, with `invocation: 'no-user'` — the `'no-model'` variant does not reproduce it). Clears CI run-step 11, the first blocker in the entire workflow.
- **The mirror generator deletes shipped skill files silently**: makes the prune archive to `.claude/.switchboard-pruned/` instead of unlinking, isolates each skill's archive in its own `try`/`catch` (a thrown `renameSync` currently aborts the loop *and* the ledger rewrite immediately strands the remainder permanently), reports pruned names on `MirrorResult`, and splits `mirror:check`'s single remedy into one per bucket — because `missing` means the mirror is *ahead* of the generator and regenerating destroys the evidence.
