# Unattended Board Progression — Completion Reports, Scoped Autoban, Teams of Teams

**Complexity:** 5

## Goal

Make it possible to leave Switchboard running and have cards progress through the board on their own. Everything here serves that one outcome.

The blocker underneath all of it: **no agent can tell the extension it has finished.** There is no such endpoint. Every mechanism that needs to know when work completed therefore *infers* it — autoban dispatches on a timer, the orchestrator `stat`s a handshake file's mtime, the plan watcher reads a plan file's mtime advance. Inference fails toward doing the wrong thing unattended; a report fails toward stopping. For a board nobody is watching, "stalls and waits" is recoverable and "advances wrongly for an hour" is not.

Alongside that, autoban carries two pieces of legacy that make it worse than it needs to be: a `multi-column` mode that automates precisely the judgement transitions it should not, and a per-role terminal-pool rotation whose purpose — spreading context load — is now covered by the `clear` command and by agent teams.

## How the Subtasks Achieve This

- **Turn-End Notification**: when a dispatched seat goes quiet, message the agent waiting on it — its head, or the orchestrator — naming the seat and whether it finished or is blocked. The signal already exists and is CLI-agnostic (`PlanIngestionEngine.ts:376-401`: output silence is the turn boundary, the plan-file mtime only disambiguates finished from blocked); nothing listens to it. This is the safeguard for an agent that never reports back on its own, and the same gate autoban advances on. **No endpoint, no hooks, no agent-side obligation** — that design was built and removed on 2026-08-08 because it worked for one CLI and silently degraded for the rest.
- **Autoban: Delete `multi-column` and `antigravity-batch`, Scope It to PLAN REVIEWED → CODED**: deletes the `multi-column` mode outright (~370 lines of UI plus its logic sites) and the `antigravity-batch` ghost, which is already retired in all but name. Removing the two values from the whitelist is the entire migration — no shim, no mapping table, no upgrade notice. Then **hard-codes the transition**: `sourceColumn` and its picker go, because a configurable source column lets the surviving mode automate exactly the judgement transitions `multi-column` is being deleted for. Finally replaces the clash-avoidance timer by subscribing to the turn-end signal the watcher already derives, keeping a timeout only as a **stall watchdog** that reports a stuck card rather than dispatching past it. The global session cap goes with the timer it bounded.
- **Retire Autoban's Terminal Pools**: removes `terminalPools`, `managedTerminalPools`, `poolCursor` and the per-terminal `sendCounts`, the round-robin rotation, and the verbs, commands and **two** UI copies that maintain them. Dispatch resolves to a named terminal or a team head instead of a pool slot — which is also what a completion report needs, since it identifies a child by `agentInstanceId`, not by ring position. `sessionSendCount` / `globalSessionCap` are left alone here — not because they survive, but because the autoban card deletes them alongside the timer they bound.
- **Retire the Orchestrator's Bespoke Machinery**: deletes the wake cadence, the file inbox, the `last-wake-complete` handshake and the batch-into-one-worktree dispatch, and rewrites the persona as an agent that reads the board, messages the team leads that already exist, and handles merge-back. Nothing new is built: agent-to-agent messaging already ships (`ptySendPrompt`, plus the callback standing order every team member carries), the board already persists what is in flight, and the turn-end notification card covers the lead that never reports. Ordering is a safety property — the cadence is currently the only thing that restarts a stalled orchestrator, so it goes last.

Everything here is deletion plus one small listener. The orchestrator was built as a subsystem the extension drives — spawn it, wake it, dispatch on its behalf, track its progress — because when it was written nothing could message an agent. That is no longer true, so most of the machinery is scaffolding around a skill file.

The split between autoban and the orchestrator is the design: **autoban owns the mechanical transition, the orchestrator owns the judgement transitions.** Into PLAN REVIEWED and into CODE REVIEWED need a human's output checked, so automating them produces work nobody trusts. That boundary is not a limitation to engineer around — it is the correct line, and this feature draws it explicitly rather than leaving it implied.

## Dependencies & sequencing

**Shipping order:** autoban deletions (changes 1-3) → pools → turn-end notification → autoban change 4 → orchestrator retirement. Nothing here waits on new infrastructure; every signal this feature consumes exists at HEAD.

- **Nothing needs a new endpoint.** Agent-to-agent reporting already ships — `POST /terminals/verb/ptySendPrompt`, documented in two skills, with `AGENT_GROUP_CALLBACK_INSTRUCTION` (`teamWiring.ts:46`) installing "report to your head when you finish" as a standing order on every team member. Sending a prompt to an idle terminal starts a turn; that is the wake.
- **Completion is already detected, CLI-agnostically.** `PlanIngestionEngine.ts:376-401`: output silence on a dispatched seat is the turn boundary, and the plan-file mtime only disambiguates `clearWorkingState` (finished) from `setBlockedState` (stopped, waiting on a human). `clearWorkingState` returns a true-transition boolean, which is the single-fire gate both the notification card and autoban hang off. Confirm it fires once and drives both rather than each adding its own guard.
- **Agent-reported completion is off the table, permanently.** It was built on Claude Code lifecycle hooks and **removed on 2026-08-08** (`feature_plan_20260807103100_agent-emitted-completion-via-cli-hooks.md`): hooks are Claude-Code-only, so the board lit correctly for one CLI and silently fell back to a blind timer for every other agent, meaning different things per seat. It also added real attack surface — an authenticated endpoint, an HMAC minter, a per-terminal token in the pty environment, a secret readable via `ps`. No card here reintroduces any of it.
- **The mode deletions need no shim.** `normalizeAutobanConfigState` (`autobanState.ts:307-309`) validates `automationMode` against a whitelist and falls back to `'single-column'`. Removing the two values from that array *is* the migration — any persisted value fails `.includes()` and lands on `single-column`. No mapping table, no compatibility path, no upgrade notice. Persisted `sourceColumn` values are likewise ignored once the field is gone, not migrated.
- **PLAN REVIEWED → CODED is enforced in code, not described in a dropdown.** `sourceColumn` currently lets autoban be aimed at any column, which is `multi-column`'s defect surviving under the other mode's name. The field, its picker and its role resolution go; one exported constant defines the transition and all four call sites read it.
- **The pools UI is three sections, not one.** `kanban.html:11149-11257` is the multi-column copy, `:10766-10901` is a separate single-column copy, and `:6638` is a controls-strip entry point outside both. **Fixed order: the autoban deletions land first** (taking the multi-column copy with the branch), then the pools subtask removes the single-column copy, the controls-strip button, both config shapes, the rotation, the verbs and the VS Code commands behind them. Both edit `kanban.html`, so per the project PRD's one-stream-per-file rule they serialise rather than run in parallel.
- **`scheduler` and `orchestration` are out of the deletions.** Scheduler runs timed jobs, a different concern from board progression.
- **The global session cap goes with the timer.** `globalSessionCap` / `sessionSendCount` hard-stop the engine at 200 dispatches (`_stopAutobanForExhaustion`) — a blast-radius bound for a clock that dispatches whether or not anything finished. Report-paced dispatch is one-in-one-out and cannot outrun itself, so the cap's only remaining effect is halting an unattended board at an arbitrary number. The autoban card deletes it in the same change that removes the timer; the pools card leaves it alone so that starting state is predictable.
- **The orchestrator does not own its team leads.** It messages leads that are already running. A team's members spawn automatically when an unparented terminal whose role heads a team is created — that path works today — so nothing needs leads to be the orchestrator's delegate children. No recursion, no depth limit, no parentage bookkeeping, and none of the fork-bomb risk that came with them.
- **No durable in-flight state.** Cards, columns, `dispatched_at`, `blocked_at` and worktrees are already persisted. An orchestrator that wakes re-reads the board; a bespoke store would duplicate it and then need reconciling against it.
- **The turn-end notification must land before the wake cadence is deleted.** The cadence is currently the only mechanism that restarts a stalled orchestrator; removing it first converts a stall into a silent stop — the worst failure for a board left running unattended. Verify a real push before touching it.
