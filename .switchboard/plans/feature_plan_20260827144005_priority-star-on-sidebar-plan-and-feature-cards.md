# Add priority star to sidebar project panel plan and feature cards

## Goal

The kanban board already has priority star capability — a clickable star icon on each card that toggles `priorityStarred` and affects ordering (starred cards sort first outside STAGING). However, the sidebar project panel (the Plans tab and Features tab in `project.js`) renders plan cards and feature cards without any priority star UI.

Users who manage plans from the sidebar cannot star or unstar them, and starred plans show no visual indication of their priority status in the sidebar list. This creates a disconnect between the board view (where starring is visible and actionable) and the sidebar view (where it's invisible).

**Root cause:** The priority star feature was added to `kanban.html` (the board webview) but was never extended to `project.js` (the sidebar/project panel webview). The two webviews are separate HTML/JS contexts with separate rendering functions (`renderKanbanCard` in kanban.html vs `renderKanbanPlans` / `renderFeaturesList` in project.js).

## Complexity Audit

### Routine
- The star button SVG and CSS already exist in `kanban.html` (lines 1164-1178, 9584-9587) and can be copied verbatim into `project.html` / `project.js`.
- The DB update path already exists: `KanbanProvider.setPriorityStarred(workspaceRoot, planId, starred)` (KanbanProvider.ts:8695) handles the toggle, updates the DB, and refreshes the board.
- The sidebar's `renderKanbanPlans` and `renderFeaturesList` functions already build cards with action buttons using template strings — the star button slots into the existing `kanban-plan-actions` div.
- The completed-card suppression pattern (`plan.column === 'COMPLETED'`) matches the board's `createCardHtml` (kanban.html:9481).
- `escapeHtml` is available in `project.js` (line 3439) and is the correct escaping function for the sidebar context (the sidebar uses `escapeHtml`, not the board's `escapeAttr`).

### Complex / Risky
- **`priorityStarred` is NOT in the sidebar's data payload.** The plan's original claim that "the sidebar already receives plan data including `priorityStarred`" is false. `_getKanbanPlans` (PlanningPanelProvider.ts:7526-7543) maps 15 fields and does NOT include `priorityStarred`. The `KanbanPlanSummary` interface (line 145-162) lacks the field. `project.js` has zero references to `priorityStarred`. Both must be added.
- **Verb allowlist regeneration.** `setPriorityStarred` is in `KANBAN_VERBS` (board's allowlist) but NOT in `PLANNING_VERBS` (project panel's allowlist). The standalone host routes project panel messages through `handleServiceVerb` → `PLANNING_VERBS.has(verb)` guard (PlanningPanelProvider.ts:222). Without adding the verb to `PLANNING_VERBS`, the standalone host rejects the message. The allowlist is auto-generated by `npm run catalog:generate` from `case` arms in `_handleMessage`.
- **Standalone composition-root wiring.** `bootstrap.ts` does NOT call `planningProvider.setKanbanProvider(kanbanProvider)` or `kanbanProvider.setPlanningPanelProvider(planningProvider)`. The extension wires both (extension.ts:1375-1376). Without these seams, `this._kanbanProvider` is `undefined` in standalone and the star toggle is a silent no-op.
- **Sidebar refresh after toggle.** `KanbanProvider.setPriorityStarred` calls `_refreshBoard` (refreshes the board webview only). The sidebar is a separate webview and will not update unless the handler in `PlanningPanelProvider` re-fetches plans and pushes `kanbanPlansReady` to the project panel.

## Edge-Case & Dependency Audit

- **Message routing:** The sidebar webview uses `vscode.postMessage` to communicate with `PlanningPanelProvider`, while the board webview uses `postKanbanMessage` to communicate with `KanbanProvider`. In the extension host, `vscode.postMessage` goes directly to `_handleMessage`. In the standalone host, WebSocket messages route through `planningVerb` → `handleServiceVerb` → `PLANNING_VERBS` guard → `_handleMessage`. Both paths converge on `_handleMessage`, but the standalone path requires the verb to be in `PLANNING_VERBS`.
- **Completed cards:** The board suppresses the star on completed cards (`const starBtn = isCompleted ? '' : ...` at kanban.html:9585, where `isCompleted = card.column === 'COMPLETED'` at line 9481). The sidebar must do the same: `plan.column === 'COMPLETED'`.
- **Feature cards:** The sidebar's feature list shows features as expandable items with subtasks. A star on the feature header stars the feature's plan record (features are plans with `isFeature: true`). Subtask starring is not in scope (subtasks are shown in a nested list, not as individual cards). This matches the board, which renders star buttons on feature cards too.
- **Re-render stability:** The sidebar re-renders on every `kanbanPlansReady` message. The star state persists across re-renders because it's in the plan data (`priorityStarred` field, once added to `_getKanbanPlans`).
- **Filtering:** The sidebar has search/filter UI. Starred plans still appear when filtered (starring is independent of filtering).
- **Board → sidebar refresh:** When a star is toggled from the BOARD, `KanbanProvider.setPriorityStarred` calls `_refreshBoard` but does NOT currently send `refreshKanbanPlans` to the project panel. The column-move handler does (KanbanProvider.ts:8768). Adding the same `refreshKanbanPlans` push to `setPriorityStarred` ensures the sidebar updates in real-time when starring from the board.
- **Standalone parity:** The `setPlanningPanelProvider` / `setKanbanProvider` wiring gap in `bootstrap.ts` is a pre-existing divergence that affects multiple PlanningPanelProvider handlers (e.g., `copyKanbanPlanPrompt` at line 3879, `deleteFeature` at line 4175). Fixing it for this feature also fixes those pre-existing silent failures.

## Dependencies

None — this plan is self-contained.

## Adversarial Synthesis

Key risks: (1) wrong message/method names would make the star button a silent no-op — fixed by using the real `setPriorityStarred` message and method; (2) `priorityStarred` absent from sidebar data payload would make the star always render unstarred — fixed by adding the field to `KanbanPlanSummary` and `_getKanbanPlans`; (3) standalone composition-root wiring gap would make the feature extension-only — fixed by wiring `setKanbanProvider` / `setPlanningPanelProvider` in `bootstrap.ts`; (4) missing verb allowlist entry would cause standalone to reject the message — fixed by running `npm run catalog:generate` after adding the `case` arm. Mitigations: all four are verified against source code with exact line references.

### 5. Handle `setPriorityStarred` in `PlanningPanelProvider._handleMessage` (src/services/PlanningPanelProvider.ts)

Add a `case 'setPriorityStarred'` to the `_handleMessage` switch. The method on KanbanProvider is `setPriorityStarred(workspaceRoot, planId, starred)` (KanbanProvider.ts:8695) — NOT `togglePriorityStar`.

```typescript
case 'setPriorityStarred': {
    const wsRoot = String(msg.workspaceRoot || workspaceRoot);
    const planId = String(msg.planId || msg.sessionId || '');
    const starred = !!msg.starred;
    if (!planId || !wsRoot) break;
    if (!this._kanbanProvider) {
        this.postMessageToProjectWebview({ type: 'showStatusMessage', message: 'No kanban provider', isError: true });
        break;
    }
    try {
        const result = await this._kanbanProvider.setPriorityStarred(wsRoot, planId, starred);
        if (!result.success) {
            this.postMessageToProjectWebview({ type: 'showStatusMessage', message: result.error || 'Failed to set priority star', isError: true });
        }
        // Refresh the sidebar — same pattern as deleteFeature (line 4190-4192),
        // addSubtaskToFeature (line 4132-4134), etc. _refreshBoard inside
        // setPriorityStarred refreshes the BOARD; this push refreshes the sidebar.
        const allPlans = await this._getKanbanPlans(wsRoot);
        const effectiveRoot = this._resolveEffectiveWorkspaceRoot(wsRoot);
        this.postMessageToProjectWebview({ type: 'kanbanPlansReady', plans: allPlans, workspaceRoot: effectiveRoot, requestId: Date.now() });
    } catch (err) {
        console.error('[PlanningPanelProvider] setPriorityStarred failed:', err);
    }
    break;
}
```
