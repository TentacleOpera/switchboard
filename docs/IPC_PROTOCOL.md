# IPC Protocol Index — webview ↔ host `postMessage` layer

> **Scope.** This index covers the `postMessage`-based message-passing layer between webview
> JS and the extension/browser host, **in both directions**:
>
> - **webview→host** — `vscode.postMessage({ type: '...' })` calls in `src/webview/*.js` and
>   the corresponding `case 'messageType':` arms in the `*PanelProvider.ts` `_handleMessage`
>   switches.
> - **host→webview** — `this.postMessage({ type: '...' })` (KanbanProvider / TaskViewerProvider)
>   and `this.postMessageToWebview({ type: '...' })` (PlanningPanelProvider / DesignPanelProvider)
>   calls in providers, plus the `if (message.type === '...')` / `case` handlers in the webview
>   JS message listeners.
>
> **Out of scope.** The browser-host WebSocket transport (`src/webview/transport.js`) is a
> separate protocol layer and is NOT indexed here. The `terminals.js` panel additionally talks
> to the host via HTTP verbs (`fetch('/terminals/verb/*')`, `fetch('/kanban/verb/*')`) and raw
> terminal WebSockets — those are the verb-engine / terminal-stream layers, also not indexed
> here; only its two `window.parent.postMessage` calls are listed below.
>
> **Line references are approximate (±20 lines) and regenerable.** This doc is designed to be
> regenerated by an agent in a few minutes — exact line numbers drift as files evolve. The
> *set* of message types per panel is the stable value.
>
> **Method-name note.** Host→webview push methods differ by provider:
> - `KanbanProvider.ts`, `TaskViewerProvider.ts`, `TicketsPanelProvider.ts`, `SetupPanelProvider.ts`
>   define `postMessage(msg)` (fans out to the active panel webview).
> - `PlanningPanelProvider.ts`, `DesignPanelProvider.ts` define `postMessageToWebview(msg)`
>   (fans out to the planning webview and, for planning, the project webview too).
>
> **Last regenerated:** Aug 2026.

## How to regenerate this index

1. **webview→host:** `grep -nE "vscode\.postMessage\(\{[^}]*type:\s*['\"]([^'\"]+)['\"]" src/webview/<panel>.js`
   (for `terminals.js` use `window\.parent\.postMessage`). Then match each type to its
   `case '<type>':` arm in the provider: `grep -nE "^\s*case ['\"]<type>['\"]\s*:" src/services/<Provider>.ts`.
2. **host→webview:** `grep -nE "this\.postMessage\(?\(\{[^}]*type:\s*['\"]([^'\"]+)['\"]" src/services/<Provider>.ts`
   (Kanban/TaskViewer/Tickets/Setup) or `this\.postMessageToWebview\(\{[^}]*type:\s*['\"]([^'\"]+)['\"]`
   (Planning/Design).
3. Line numbers drift; the *set* of types per panel is the stable value. Mark refs approximate (±20).
